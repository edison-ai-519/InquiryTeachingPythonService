# 图谱节点知识库绑定与图谱优先检索设计

## 1. 背景与目标

当前知识图谱节点只有数据来源标签，没有可配置的 RAG 知识库绑定关系。聊天链路会把选中的图谱节点转成查询，并复用当前专家可访问的课程知识库，但无法表达“某个节点应优先检索哪些知识库”。

本次改造目标：

1. 允许每个知识图谱节点绑定一个或多个已有的 `curriculum_sources.source`。
2. 用户选定图谱链路时，始终以图谱链路为主回答依据。
3. 节点绑定知识库时，使用节点绑定 source 与当前专家授权 source 的交集进行 RAG 检索。
4. 节点未绑定知识库时，回退到当前专家已授权的 source。
5. RAG 只补充背景知识；没有命中、未配置或因权限过滤为空时，仍可基于图谱链路正常回复。
6. 记录节点配置、权限过滤、回退原因和命中来源，保持可审计。

## 2. 范围与非目标

### 本次范围

- 图谱节点与现有课程知识库 source 的持久化关联。
- 图谱 JSON 导入时的节点知识库绑定。
- 管理员配置节点知识库的接口。
- 图谱候选/选中后的 source 解析与 RAG 检索策略。
- 聊天 RAG 上下文的图谱优先表达和检索审计。
- 单元测试与聊天集成测试。

### 非目标

- 新建独立的通用知识库实体体系。
- 改造现有课程文件上传、切片、向量化和权限模型。
- 增加前端完整的节点知识库管理页面；本次先提供后端能力和必要的数据返回字段。
- 改变非图谱场景下已有专家 RAG 行为。

## 3. 数据模型

新增关联表 `knowledge_entity_sources`：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `entity_id` | `VARCHAR` | 主键之一，外键到 `knowledge_entities.id`，级联删除 | 图谱节点 ID |
| `source` | `VARCHAR` | 主键之一，外键到 `curriculum_sources.source`，级联删除 | 已存在的知识库 source |
| `created_at` | `VARCHAR` | 非空 | 绑定创建时间 |

使用复合主键避免重复绑定，并为 `source` 建索引以支持知识库删除和反向查询。现有 `KnowledgeEntityModel.source` 继续保留，表示节点自身的数据来源，不再承担 RAG 知识库绑定语义。

图谱导入节点支持：

```json
{
  "id": "insect_aphid",
  "name": "蚜虫",
  "entity_type": "insect",
  "rag_sources": ["自然教育资料.docx"]
}
```

导入时对 `rag_sources` 去重、规范化，并校验 source 是否存在。不存在的 source 作为导入错误返回，整个导入事务回滚，避免产生“看似已配置但实际不可检索”的绑定。

## 4. 接口设计

### 4.1 图谱查询返回

实体序列化结果增加：

```json
{
  "id": "insect_aphid",
  "rag_sources": ["自然教育资料.docx"]
}
```

候选图谱、邻居图谱和选中图谱都返回该字段，使前端能显示节点是否配置知识库。

### 4.2 管理员配置接口

新增管理员接口：

`PUT /api/knowledge/graph/entities/{entity_id}/rag-sources`

请求体：

```json
{
  "sources": ["自然教育资料.docx"]
}
```

接口校验节点存在、source 存在，替换该节点的全部绑定并返回规范化后的 source 列表。空列表表示清除节点专属配置，聊天时按“未配置”回退。

## 5. 检索与上下文数据流

### 5.1 source 解析

聊天请求选择专家后，先取得专家已授权 source。用户提交有效图谱选择后，收集选中图谱中涉及的实体 ID（包括显式选择的节点，以及所选关系/路径的两端节点）：

1. 若任一选中节点配置了 source，取所有已配置 source 的并集。
2. 与专家授权 source 求交集，形成实际可检索 source。
3. 若没有任何选中节点配置 source，回退使用专家授权 source。
4. 若节点有配置但交集为空，不再扩大到未授权 source；记录 `configured_but_not_allowed`，仍使用图谱上下文回复。

为避免多节点查询重复和结果失控，按节点生成查询，最多处理现有策略允许的节点数量，并把实际 source 过滤交给现有 `CurriculumKnowledgeService.retrieve`。

### 5.2 上下文优先级

有图谱选择时，上下文按以下顺序拼接：

1. 会话资料；
2. 用户选定的图谱链路；
3. 节点 RAG 背景片段；
有图谱选择时不再额外执行一遍普通专家课程 RAG，避免未关联内容稀释图谱主线。没有图谱选择时，才按现有规则拼接普通专家课程 RAG：

1. 会话资料；
2. 普通专家课程 RAG。

图谱上下文使用明确的 `<knowledge_graph_reference>` 标记，RAG 使用 `<graph_rag_reference>` 或现有课程参考标记。提示词中明确：图谱链路是本轮主回答依据，RAG 只用于解释背景、补充定义或提供教学资料，不得把 RAG 中未被图谱支持的内容伪装为图谱事实。

当检索关闭、检索异常、source 未配置、权限交集为空或没有命中时，不阻断主流程；只在审计 source 中记录对应状态，图谱链路仍传给 LLM。

### 5.3 非图谱兼容性

没有 `graph_selection` 时，保持当前行为：选中专家且存在授权 source 时执行普通课程 RAG；有有效图谱选择时，仅执行按节点 source 解析后的图谱 RAG。主导师和草案路径保持现有逻辑，不因本次节点绑定改造而自动查询课程库。

## 6. 审计记录

在现有 `rag_records.source_json` 中保留兼容字段，并在图谱记录中增加：

```json
{
  "graph": {
    "selected_entity_ids": ["insect_aphid"],
    "configured_sources": ["自然教育资料.docx"],
    "allowed_sources": ["自然教育资料.docx"],
    "effective_sources": ["自然教育资料.docx"],
    "fallback_reason": "",
    "source_resolution": "node_configured",
    "rag_node_queries": [],
    "hit_sources": [],
    "records": []
  }
}
```

`source_resolution` 至少区分：`node_configured`、`expert_fallback`、`configured_but_not_allowed`、`no_expert_permission`。字段缺失时现有审计读取逻辑继续按旧格式工作。

## 7. 错误处理

- 导入或配置接口收到不存在的 entity/source：返回 400/404，并回滚变更。
- 普通用户访问配置接口：沿用管理员权限依赖，返回未授权。
- RAG 服务异常：沿用现有降级逻辑，图谱上下文不丢失，审计记录保存错误信息。
- 节点绑定 source 被删除：通过外键级联清理绑定；序列化时返回空绑定列表。
- 图谱选择校验失败：保持现有 warning 行为，不执行选中图谱 RAG。

## 8. 测试策略与完成标准

新增或扩展测试覆盖：

1. 图谱导入可保存节点 source 绑定，并拒绝不存在的 source。
2. 管理员可替换节点 source，普通用户不能配置；空列表可清除绑定。
3. 节点已配置且专家有权限时，仅检索节点 source 与专家权限的交集。
4. 节点未配置时，检索回退到专家授权 source，并记录 `expert_fallback`。
5. 节点已配置但无权限时，不越权检索，并记录 `configured_but_not_allowed`。
6. 图谱链路始终进入上下文；RAG 无结果或异常时聊天仍能完成。
7. 无图谱选择的专家 RAG 回归测试保持通过。

完成标准：上述测试通过，现有测试套件通过，数据库迁移可在空库和已有库上成功执行，图谱接口返回绑定字段，且审计记录能区分节点配置与专家回退。
