# 工作台用户体验验证脚本

## 目标与记录方式

每类角色招募 5 名未使用过当前工作台的用户。测试期间不展示使用手册，不提供口头操作提示；用户停住时记录求助，不代替操作。教师和家长各安排 3 人从新建流程开始、2 人从预置的已发布测试任务开始；研学基地用户均从新建项目开始。每人记录：任务是否完成、完成用时、求助次数、是否能指出当前下一步，以及能否正确判断方案已保存。

首轮目标：每类至少 4/5 人独立完成任务；每类至少 4/5 人正确判断保存状态和下一步。若未达到，记录卡点发生的页面、用户原话和误操作，再调整提示内容或时机后复测。

请使用隔离的测试账号和测试项目。研学项目发布、任务领取、报告提交会写入系统数据，不要在生产项目中执行验证脚本。

## 教师工作台

**给参与者的任务：** 为三年级学生设计一课时的“光的传播”探究课。教室有手电筒、白纸和镜子。如果从任务大厅开始，领取“光的传播探究教学设计”测试任务；否则创建课题。向主导师说明情况，查看建议后整理右侧方案，保存当前阶段并进入下一阶段。

**观察点：** 是否找到创建入口；是否知道如何描述年级、目标、课时和材料；是否区分主导师与领域专家；编辑后是否找到保存状态；是否理解推进阶段会提交当前内容。

## 家长工作台

**给参与者的任务：** 孩子 8 岁，在阳台看到雨后叶片上的水珠。家里有放大镜，可陪伴 30 分钟。如果从任务大厅开始，领取“雨后水珠亲子探究”活动测试任务；否则创建家庭探究活动。补充家庭条件，向主导师说明观察情况，整理并保存方案，再进入下一阶段。

**观察点：** 是否理解家庭情况可选填；是否知道如何说明孩子年龄、观察和可用材料；是否找到方案编辑和保存状态；是否能判断下一步。

## 研学基地工作台

**给参与者的任务：** 为“古道自然观察”创建一个研学项目，填写地点、场景和物料，为教师工作台添加并发布半天观察任务，找到报告汇总区并说明如何整理项目成果。

**观察点：** 是否找到项目协同入口；是否知道先建项目、再配场景和任务；是否识别任务的目标工作台和工作流；是否找到报告查看与人工汇总入口。

## 失败状态检查
